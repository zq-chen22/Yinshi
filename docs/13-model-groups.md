# 模型组：一个飞书对话，两种执行引擎

本功能是 0.4.6rc1 的可选能力。未配置 Claude 的机器仍能使用 Codex。给同一台主机注册两个飞书机器人或运行两个消息监听服务都不是必要条件。

## 怎么发消息

把口令**单独发成一条文字消息**。英文组名不区分大小写；例如“c组高级”和“C组高级”完全相同。“请介绍 C组高级”是问题，不会切档。

| 整条消息 | 下一任务使用的主组 |
|---|---|
| 默认 / 高级 | 本机配置的 Codex 默认 / 高级 |
| C组默认 | Claude Code · Opus 5.5 · medium |
| C组高级 | Claude Code · Fable 5.2 · high |
| 全部C组默认 / 全部C组高级 | 本机所有已绑定的活动对话和机器人的私聊切到相应 C 档 |
| 全部默认 / 全部高级 | 批量切回 Codex，沿用原档位及 Random 规则 |
| 模型档位 | 查看档位定义和当前主组 |

批量口令仅配对管理员可用；不会修改其他主机或新对话的初始档位。已在执行的任务不会换引擎。显式选 C 组时也包括 Random；切回 Codex 后 Random 恢复该组高级及 Fast。C 的默认/高级是它自己的 effort，没有继承 Codex Fast。

## 跨组回答，不是口令

例如：“请让另一组独立回答：给这个栏目起三个中文名字。”“请双方一起回答这个问题。”也可以在飞书**引用原题**后说“请做高级交叉验证”。这些都是普通自然语言，只有负责解释该条消息的主模型发起协作动作，才会产生外部调用。

- 指定一方或普通“交叉印证”：除非另有要求，其他组选与主组同一逻辑档位；普通交叉印证不额外调用主组盲答。要求双方一起答则包括主组。
- “高级交叉验证”：所有可用组（包括主组）分别用高级档，任务结束后不改变主组。一个模型用于识别协作请求的调用，与独立回答的调用是两件事；会分别消耗对应渠道的额度。
- 桥取得同一聊天中的用户原文：可用本条题面、明确引用的原题，或上一个可核验的用户问题。一条消息包含题面和委托语时，只接受原文中唯一、逐字匹配的题面；含糊时应澄清。建议直接引用，避免把别的问题送出。
- 各组并行在新上下文中只看到原题与按该题授权的附件。不注入其他组的答案或主持模型的意见，不让咨询模型再委托。桥分组标注来源、原样发送回答；某组超时、余额不足、附件格式不兼容或答复疑似含密钥时，保留其他组结果并标出原因，不偷偷换模型、重答或改写。
- 飞书公式使用纯文字，而非 LaTeX。公式写法是所有组的通用展示规则，不给盲答者添加解题提示。

## 日志、权限与恢复

持久对话在其授权工作目录下共用一份“vibe_log/对话标题.md”；同名不同对话会消歧，改名或切模型不另起一份。各参与模型的署名、问题与可核验答复摘要由桥串行追加、去重，按北京时间记录。工作模型先读项目约定和日志，盲答模型不读该日志。Codex 和 Claude 仍有各自原生会话，切换不代表复制私有推理、工具状态或完整聊天历史；需要交接的事实应写入主题日志。私聊临时模式不恢复上一轮的原生 Claude 会话。

Claude 的停止、追加、进度卡和可交付文件复用同一桥队列。追加会中止旧生成，带着补充在同一原生会话继续；不是两个同时运行的任务。强制中断若没有保存最终结果会明确报告未确认，不自动重放可能有副作用的动作。C 主任务本身不调用 Codex；只有明确委托给 Codex 时才需要 Codex 额度。新的外部模型请求使用相应渠道的真实额度。

## 在另一台主机上配置（不会随 Git 分发凭据）

1. 安装并验证该机的官方 Claude Code 客户端与 Linux bubblewrap。当前适配器针对明确支持官方 Claude Code 的 4Router 渠道，不模拟客户端、不直发不受支持的 Messages API。
2. 将**该机获授权**的 4Router 令牌置于桥的 config.toml 同目录下的“claude-4router.key”；须为本机服务用户所有、权限 600 的普通文件，不能是符号链接。不要将令牌放在聊天、Git、日志或示例文件。桥只向固定的渠道地址鉴权。
3. 使用正规原生 CLI、独立用户配置和会话目录；按用户实际权限运行。受限的工程只能访问授权工作区和当轮附件；只读不会放开 Bash 或写入；不支持的隔离条件直接报错。原生私有会话、队列和凭据不跨主机复制。
4. 使用独立测试目录及测试数据库，先禁用 Codex、检查 C 双档、续聊、工具、停止、追加，再用合成原题测试双向委托和并行高级回传。测试无须向真实飞书群发消息。确认空闲后才激活发布包。

可在 TOML 的 model_groups 下增加其他使用**现有 Claude 后端**的组。每组定义 default 和 advanced，各含 model、effort；例如小写 d 对应“D组默认 / 全部d组高级”。引入不同供应商需要新增独立后端，并验证权限与附件、取消、原文隔离及记账；不能只换一个模型名就假定兼容。
